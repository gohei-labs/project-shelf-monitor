Validate the registry scope field

This review asks for approval to make the registry integrity gate reject a missing or invalid rule scope — schema hardening so scope is validated like domain and code are.

Requested Approval

  1. Enforce scope. check-registry.ps1 (GOV-02) now requires every rule to declare a scope, and rejects any value outside generic / bilingual / product. The check mirrors the existing domain validation and fails locally and in CI. All 37 current rules pass unchanged.
  2. Defer stack. scope: stack stays intentionally rejected until the first stack declaration; adding it is part of the deferred schema work and will extend this same allowed set deliberately — so the value cannot be set prematurely.

Risk

Low. Checker-only change — no registry data, rule wiring, or monitor output is touched, and all 37 rules already carry a valid scope. The one thing to remember: when scope: stack is introduced, the allowed set here must be extended in the same change. That is deliberate — a new scope value should force a conscious edit to the gate rather than slip in silently.

Not Decided Here

  • Catching a valid-but-wrong-layer scope (as in #101): that stays a classification-test / human-review judgment - an enum check cannot decide the correct layer.
  • Introducing scope: stack and re-scoping backend-checks / frontend-build (at the first stack declaration).
  • Whether the merge gate itself is enforced — Issue #102 (plan-gated; a separate owner decision).
  • Widening GOV-02's rule text to enumerate the fields it validates (its prose stays generic today).
