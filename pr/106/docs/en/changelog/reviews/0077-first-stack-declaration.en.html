First stack declaration

This review asks for approval of the project's first component declaration: project-components.json declares the api component (stack backend-python) with a minimal verified FastAPI skeleton at apps/api, and the registry gains scope: stack — the final schema step of the stack onboarding.

Requested Approval

  1. Declare the api component. project-components.json (new, the component contract from the development rules): id api, path apps/api, type backend, stack backend-python, commands.check = uv run ruff check && uv run pytest. The contract gate (ENV-03) now validates a real manifest — an undeclared implementation directory fails CI.
  2. Accept the skeleton. apps/api: FastAPI on Python 3.12 (pinned by .python-version + uv.lock), one /health route, one passing test, ruff configured. No file operations and no managed-root access (PROJ-01 respected). The declared check command runs green locally (CPython 3.12.13, aarch64).
  3. Open the stack layer. scope: stack joins the gate's allowed set (reserved since 0065) and backend-checks / frontend-build move product → stack. They stay future controls (enforcedBy: null) and stay on the Project rules view, which now shows product + stack scopes. Activation (wiring the declared checks into CI) is deliberately a separate next step.

Risk

Medium, honestly bounded: the declaration is real but the stack gates are not yet wired — nothing runs uv run ruff check && uv run pytest in CI, so a broken api component would not block a merge until the activation step lands. This is the same graduation path every advisory rule follows (declare visibly first, enforce next). The skeleton itself is minimal, verified locally, and adds no file-operation surface. Mitigation: ENV-04's note names the gap; activation is the named next step.

  • Phase 1 behavior (read-only shelf, managed-root boundary, JSONL logs — REQ-001..004) — arrives as implementation changes on this skeleton.
  • Compose services / Dev Container integration for the api — part of Phase 1 runtime work, not the declaration.
