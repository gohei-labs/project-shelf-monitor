モニターをセキュリティとプロセス品質のビューに分割する

この資料は、ガードレールモニターを「プロセス品質」（日々の作業を安定させるルール）と「セキュリティ」（事故・攻撃への保護層）の2ビューに分けることの承認を求めます。

承認のお願い（Requested Approval）

  1. レジストリに domain フィールドを追加する。セキュリティ系6件（権限境界・実行前フック・実行サンドボックス・持ち出し境界・シークレットスキャン・ブランチ保護）に domain: security を付与します。未指定はプロセス品質（既定）。正本は1つのままで、タグの付け替えだけでビュー間を移動できます（scope による Project rules ビューと同じパターン）。
  2. 専用の Security ビューを新設する。monitor/security-monitor.html / .ja.html を同じジェネレーター・同じ編集的デザインで生成し、Guardrails ビューはプロセス品質19件だけを表示します。
  3. 全生成ページのナビを統一する。順序は Guardrails → Security → 開発ルール → プロジェクトルール → 要求 → 機能 → アーキテクチャ → レビュー。

リスク（Risk）

低リスクです。データの変更はタグ追加のみで、ゲートの挙動は一切変わりません（表示の分割だけ）。分類の判断（何をセキュリティとみなすか）は domain タグの付け替えでいつでも修正でき、レジストリの整合ゲートが値の妥当性を守ります。

決めないこと（Not Decided Here）

  • セキュリティビュー独自の追加情報（脅威モデル・適用範囲の図示など）。
  • advisory ガードレールの昇格（Issue #79・#80・#81 で管理）。
  • カテゴリ体系自体の再編。
