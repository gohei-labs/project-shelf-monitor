実行前クリティカルなゲートを決定的フック（PreToolUse/Stop）へ移す

この資料は、事後（check.ps1・CI）にしか効かなかったガードを、エージェントの行動の前に作動する決定的フックへ拡張することの承認を求めます。

承認のお願い（Requested Approval）

  1. PreToolUse ガードの導入。ファイル系ツールの書込先を agent-policy/policy.json の保護パスと照合し、実行前に判定します。コマンド系ツールは、破壊的コマンドの deny ルールを権限境界の下の第二レイヤーとして照合します。
  2. 保護パスの deny / ask の使い分け。Issue #64 は4パスすべて deny としていましたが、回復不能な対象（.git/、生成物の .claude/settings.json ほか）のみ deny とし、オーナーレビューが本旨の対象（monitor/registry.json・agent-policy/policy.json・.devcontainer/）は ask（実行時点での人間承認）とします。全 deny にするとエージェントは新しいガードレールをレジストリに登録できなくなり、統制の更新自体が止まるためです。
  3. Stop ゲートの導入。ターン終了時に scripts/check.ps1 全体を実行し、失敗中は終了をブロックして失敗内容をエージェントに返します。stop_hook_active による無限ループ防止付き。
  4. フック層の生成とゲート化。フック配線は policy.json から .claude/settings.json へ生成し、レジストリに agent-pre-execution-hooks（hard-gate）を登録。フックの無効化・スクリプト欠落・enforcement 未宣言は既存ゲートの拡張で fail します。

リスク（Risk）

レイテンシ。PreToolUse はツール呼び出しごとに pwsh を起動（約0.3〜0.6秒）、Stop はターン終了ごとにチェックスイート全体（数十秒）を実行します。決定的強制の対価であり、Issue #64 で明示された要求です。

過剰ブロック（誤検知）。コマンド照合はテキストベースのため、区切り文字直後のクォート内文字列（例: コミットメッセージ中の危険コマンド）を稀に deny します。安全側の誤りであり、エージェントは表現を変えれば先へ進めます。クォート文脈の解析はサンドボックス作業（#62）に委ねます。

ハーネス依存。フック配線は現時点で Claude Code のみ。他ハーネスにはこの層が無いため、他ハーネスのエミッター追加までは事後ゲート（CI）が唯一の防壁です。なお ask は非対話実行では deny として扱われます（安全側）。

決めないこと（Not Decided Here）

  • 実行サンドボックス・egress／認証情報読み取り制御（Issue #62・#63）。
  • 他ハーネス（Codex・Gemini・Cursor）向けのフック／設定エミッター。
  • 解決後コマンドの構文解析（テキスト照合の限界の解消）。
  • Stop フックの高速化（クリーンツリー時のスキップ等の最適化）。
