必読コンテキストをセッション開始時に決定的に配達する

この資料は、「エージェントが必読文書を読んだか」を信頼する代わりに、読むべき内容そのものをセッション開始時に強制注入することの承認を求めます。品質ゲート3部作の最終弾（#80）です。

承認のお願い（Requested Approval）

  1. SessionStart フックによる全文注入。scripts/hooks/session-start-context.ps1 が、セッション開始時（再開・/clear・コンテキスト圧縮後を含む）に agent-context/agent-core-context.json の全 alwaysRead ファイル（10件・注入量 約53KB）の全文を注入します。「読んだフリ」は構造的に不可能になります — 読む/読まないの選択自体が消えるためです。
  2. コストの妥当性を承認する。注入は毎セッション約13.5kトークンですが、これは従順なエージェントが Read ツールで消費する量と同等（ツール呼び出しのオーバーヘッド分はむしろ安い）です。ルールに従った場合と同じコストで、従わない可能性をゼロにします。
  3. ゲート化とレジストリ昇格。フック配線は policy.json から生成し、既存ゲート（check-agent-policy）がフラグ有効とスクリプト追跡を検証。core-context-reading を advisory（名目）から active（hard-gate）へ昇格します。readWhenRelevant（条件付き必読）はトリガー付き一覧として注入され、該当時の読了はエージェント責任のまま — この残余も正直に記録します。

リスク（Risk）

コンテキスト常時消費。毎セッション約13.5kトークンを固定で使います。alwaysRead が肥大化すると負担も増えるため、manifest の整合ゲート（既存）に加え、肥大化はレビューで抑える運用です。将来問題になれば要約版の注入へ切り替え可能（レジストリトグルで即時停止も可能）。

適用範囲。配達は Claude Code ハーネスのみ。他ハーネス（Codex 等）はエミッター追加まで manifest ベースの手動読了のまま — 非対称は文書とレジストリ note に明記しました。

条件付き必読は残余。readWhenRelevant の読了は依然エージェント責任です（全文注入するとコストが常時2倍以上になるため、意図的に一覧のみ）。

決めないこと（Not Decided Here）

  • 他ハーネス向けの SessionStart 相当のエミッター。
  • alwaysRead の要約版注入への切り替え基準。
  • readWhenRelevant の決定的強制。
