Add a gate that detects template placeholder residue in review artifacts

This review asks for approval to add a hard gate that mechanically blocks review artifacts that still carry template placeholders before they can merge.

Requested Approval

  1. Add a hard gate that detects placeholder residue. The new script scripts/guardrails/check-review-artifact-placeholders.ps1 inspects every review artifact under docs/{en,ja}/changelog/reviews/ (excluding the template itself) and fails on any of: (1) the four-capital-N number placeholder remaining anywhere, (2) a <title> still equal to the template placeholder, (3) a leftover template usage comment block, (4) a <title> that does not contain the artifact's own four-digit number.
  2. Scan the whole tree, not only changed files. This defect slipped through human review twice in a row (0055 reached main; 0056 was caught during the PR #65 review), so the gate inspects the entire repository on every run to prevent recurrence structurally.
  3. Approve the registry entry and rule doc update. Register review-artifact-placeholders as a hard gate in monitor/registry.json, wire it into scripts/check.ps1, regenerate the guardrail monitor, and document the exact checks in the bilingual rules doc.

Risk

The main risk is false positives. To avoid flagging artifacts that legitimately discuss the template (0048 is the approval record for the template itself), the usage-comment detection is scoped to HTML comments only; mentions in visible text and titles are allowed (verified green on 0048). If a false positive still occurs, the gate can be paused visibly via the registry's enabled toggle with a recorded disabledReason, and detection changes ship as small single-intent PRs.

Not Decided Here

  • Harness/OS-level enforcement such as sandboxing and egress control — Issues #62 and #63.
