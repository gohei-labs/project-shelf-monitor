モニタをルール語彙に揃える

このレビューは プロセスモニタを「ルールモニター」に改題し、強制ゲートと申し合わせを見た目にも分かれたグループとして表示すること の承認を求めます。

承認をお願いする事項

  1. プロセス品質ページの表題を「ガードレールモニター」から「ルールモニター」へ。レビュー 0068 で採用した語彙 — 配線済みブロックゲートを持つルールだけがガードレール — に一致させる。
  2. 全モニタビューを 2 つのラベル付きグループ —「ガードレール（強制ゲート）」（hard-gate / conditional-gate）と「申し合わせ・予定・外部」— で描画する。オーナーが当初指摘した強制の区別を、カード単位のチップだけでなくページ上で一目で見えるようにする。
  3. ファイル名と URL は不変（2026-07-09 のオーナー決定）。改名は最初のスタック導入時の記録済みスキーマ変更と同時に扱う。文書の記述は「ルールモニター」と呼び、パスは monitor/guardrail-monitor*.html のまま。

変更内容

完全な一覧（このほかに変更記録 0061 の対）。

変更ファイル変更点
scripts/generate/build-guardrail-monitor.ps1表題・ラベル、ビューごとの 2 グループ表示（グループ見出し付き）、中立化した空表示・詳細の文言。
monitor/*.html更新後のジェネレータから再生成。
ルール文書（onboarding・documentation-system・handoff brief・agent-policy・application-monitoring。日英）散文の呼称を「ガードレールモニター」→「ルールモニター」。ファイルパスは不変。
scripts/generate/build-reviews-page.ps1・build-application-monitor.ps1・build-pages-site.ps1共有ナビラベル「ガードレール」→「ルール」と公開サイト入口の表題・リンク。全ページで語彙を一貫させるため。
monitor/registry.json散文 3 箇所のみ（ページ名に言及する rule 文・note・description）。ゲート・status・controlType のデータは不変。

リスク

表示のみの変更：ゲート挙動、台帳のゲート／status／controlType データ、URL は変わらない（ページ名に言及する台帳の散文 3 箇所は改称）。再生成ページは registry ゲートが同期を検証し、グループ分けは詳細チップが既に使っている controlType と同じフィールドから導出する — 新しいデータはなく、2 つの見え方が食い違うことはない。

ここでは決めないこと

  • モニタのファイル名／URL の改名（最初のスタック導入時の記録済みスキーマ先送りに合流）。
  • 台帳データやゲートの変更。
