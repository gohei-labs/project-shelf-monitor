エージェント権限境界の fail-closed 化

agent-policy/policy.json から 2 つのキーを削除するだけで、認証情報の読み取り境界と push allowlist が消えました。ゲートは緑のまま、生成された設定は何も保護せず、PreToolUse フックは任意のリモートへの push を許可しました。エンドツーエンドで再現したうえで、3 つの層すべてを修正します。

承認のお願い

  1. キー不在で fail-closed。@($policy.key).Count -eq 0 は、キーを削除した場合には発火しません。PowerShell の @($null).Count は 1 だからです。ゲートは今後、キーの不在・null・空リスト・空白エントリ（空白 prefix はすべてのリモートに一致）を拒否します。credentialDenyRead・pushRemoteAllowedPrefixes・allowBaseline に適用し、構造キー deny / protectedPaths / hooks の存在を必須化してチェックが空虚に通らないようにします。
  2. ルールが名指しする deny をすべて固定。$requiredDeny は 4 つの id しか持たない一方、SEC-01 は curl と wget のアップロードを、GOV-03 は破壊的 git コマンドを名指しします。今後は 10 件すべてを列挙します。従来は wget-upload や hard-reset を削除しても緑でした。
  3. 自己整合ではなく性質を検証。-Verify の同期チェックは、同じ弱体化ポリシーから設定を再生成して比較するため、常に「同期」しています。新チェックは生成済み .claude/settings.json を読み、各認証情報パスに対応する Read(<path>) deny ルールの存在を検証します。
  4. 実行時と生成時にも fail-closed。allowlist が不在・空・空白のとき、PreToolUse フックは明示的なリモート URL への push を拒否します。生成器は、無意味なルール Read()・Read(/**) をコンパイルする代わりに throw します。
  5. 境界の変更にレビューを強制。agent-policy/ と scripts/hooks/ を、レビュー成果物のリンクを必須とする高リスクパスに追加します。

再現：修正前と修正後

各攻撃をリポジトリの隔離コピーで実行。「修正前」は本日の main の状態です。

リスク

変更自体は低リスクで、追加するのは「拒否」だけです。いかなる境界も弱められず、正当なポリシーはそのまま通過します（確認済み）。コスト：deny ルールの廃止には今後ゲートの編集が必要になります——意図的で、scope や guidance の値を固定しているのと同じ方式です。直らないもの：$requiredDeny は依然として手で保守するため、新しい exfiltration チャネルをポリシーに足しても、ここに id を足さなければ固定されません。また本変更が修理するのは 1 つの統制面のみです——同じ監査が、UTF-16 ファイルを見逃す秘密情報スキャナを含む 26 件の fail-open を追加で確定報告しています。

ここでは決めないこと

  • 監査で確定した他の 26 件（秘密情報スキャナのエンコーディング対応、spec ゲートの実質性チェック、サンドボックスの認証情報マウント denylist ほか）——各々に個別の変更が必要。
  • scripts/tests/ を実行レーンに配線し、これらの修正を回帰から守ること。現在は何も実行していない。
  • $requiredDeny を手動一覧ではなくポリシー自身のカテゴリから導出すること。
