Claude-only agent operation

This review asks for approval to retire the Codex/Gemini-specific conventions and adapter files, making Claude Code the project's single operating agent.

Requested Approval

  1. Delete the unused root adapter entry points AGENTS.md (Codex) and GEMINI.md (Gemini). CLAUDE.md remains the only root adapter; a new adapter is added only when another tool is actually adopted.
  2. Reword the review rules to agent-neutral terminology: "AI review-only pass" replaces "Codex review-only pass" in the code-review standards and the AI review protocol. The record heading stays "AI Review Record"; the legacy "Codex Review Record" heading remains accepted so past PR records stay valid.
  3. Change the recommended branch-name prefix from codex/* to claude/*, since the agent doing the work is Claude, not Codex (owner feedback on PR #87).

Risk

Docs-only change: no gate script or CI behavior changes. The main risk is wording drift — history (change notes, past review records, merged branches) keeps the old Codex wording, and the record gate intentionally still accepts the legacy heading. Mitigation: the rules docs state the legacy acceptance explicitly, and this artifact records why historical wording is left untouched.

Not Decided Here

  • Historical records keep their Codex wording: changelog notes, past review artifacts, git history, and the paused rule LLM-GR-006's mention of Codex-bundled runtimes.
  • scripts/guardrails/check-ai-review-record.ps1 keeps accepting the legacy "Codex Review Record" heading; dropping it is not proposed.
  • Explanatory mentions of other harnesses in agent-policy.md and build-agent-config.ps1 stay: they accurately state that only the Claude harness gets generated config.
  • The external-product mention of Codex in the CodeRabbit evaluation note stays: it describes a third-party tool's capability, not this project's setup.
  • Adopting any additional AI agent in the future is a separate decision.
