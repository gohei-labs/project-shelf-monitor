レビュー資料のプレースホルダー残存を検出するゲートを追加する

この資料は、テンプレートのプレースホルダーが残ったままのレビュー資料をマージ前に機械的に止めるハードゲートの追加の承認を求めます。

承認のお願い（Requested Approval）

  1. プレースホルダー残存を検出するハードゲートを追加する。新スクリプト scripts/guardrails/check-review-artifact-placeholders.ps1 が、docs/{en,ja}/changelog/reviews/ 配下の全レビュー資料（テンプレート自身を除く）を検査し、(1) 大文字 N を4つ並べた番号プレースホルダーの残存、(2) プレースホルダーのままの <title>、(3) テンプレートの使い方コメントブロックの残存、(4) <title> に資料自身の4桁番号が無い、のいずれかで fail します。
  2. 変更分だけでなく全件を検査する方式を採用する。この欠陥は 0055（main に混入）と 0056（PR #65 のレビューで発見）と2回連続ですり抜けたため、リポジトリ全体を常時検査し、再発を構造的に防ぎます。
  3. レジストリ登録とルール文書の更新を承認する。monitor/registry.json に review-artifact-placeholders（hard-gate）として登録し、scripts/check.ps1 に配線、ガードレールモニターを再生成し、ルール文書（日英）に検査条件を明記します。

リスク（Risk）

主なリスクは誤検知です。テンプレートについて正当に言及する資料（例: 0048 はテンプレート自体の承認資料）を巻き込まないよう、使い方コメントの検出は HTML コメント内部に限定し、本文や題名での言及は許容します（0048 で緑を確認済み）。それでも将来誤検知が起きた場合は、レジストリの enabled トグルと disabledReason で見える形で一時停止できます。検出条件の変更自体は小さな単一意図の PR で行います。

決めないこと（Not Decided Here）

  • 実行前に効く決定的フック（PreToolUse/Stop）への移行（Issue #64）。
  • サンドボックスや egress 制御などハーネス/OS 側の強制（Issue #62・#63）。
  • PR プレビューリンクの完全自動化（既知の 403 コメント問題の解消）。
  • レビュー資料の内容品質（文章・構成）の自動評価。
