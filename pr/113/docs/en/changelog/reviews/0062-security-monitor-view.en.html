Split the monitor into Security and process-quality views

This review asks for approval to split the guardrail monitor into two views: process quality (the rules that stabilize everyday agent work) and Security (the protection layer against accidents and attacks).

Requested Approval

  1. Add a domain field to the registry. The six security guardrails (permission boundary, pre-execution hooks, execution sandbox, exfiltration boundary, secret scan, branch protection) are tagged domain: security; untagged means process quality (the default). The registry stays the single source of truth, and re-tagging moves a rule between views — the same pattern as the scope-based Project rules view.
  2. Add a dedicated Security view. monitor/security-monitor.html / .ja.html are generated by the same script in the same editorial design; the Guardrails view now shows only the 19 process-quality rules.
  3. Unify the top nav across all generated pages. Order: Guardrails, Security, Development rules, Project rules, Requirements, Features, Architecture, Reviews.

Risk

Low. The only data change is a tag; no gate behavior changes (display split only). The classification judgment (what counts as security) can be revised any time by re-tagging domain, and the registry integrity gate validates the values.
