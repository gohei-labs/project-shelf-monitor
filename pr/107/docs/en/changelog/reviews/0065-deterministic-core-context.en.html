Deliver the required core context deterministically at session start

This review asks for approval to stop trusting that the agent read the required documents, and instead force-inject their content at session start. Final part of the quality-gate trilogy (#80).

Requested Approval

  1. Full-content injection via a SessionStart hook. scripts/hooks/session-start-context.ps1 injects the full content of all ten alwaysRead files (~53 KB injected) from agent-context/agent-core-context.json at session start, including resume, /clear, and context compaction. "Pretending to have read" becomes structurally impossible — the choice itself disappears.
  2. Approve the cost rationale. Injection costs ~13.5k tokens per session — the same tokens an obedient agent would spend on Read tool calls (slightly less, without call overhead). The same cost as compliance, with the possibility of non-compliance removed.
  3. Gate it and promote the registry entry. Hook wiring is compiled from policy.json; the existing gate verifies the flag stays on and the tracked script exists. core-context-reading is promoted advisory → active (hard-gate). readWhenRelevant entries are injected as a path + trigger list only; reading those on a matching task remains the agent's responsibility — recorded honestly as a residual.

Risk

Constant context cost. ~13.5k tokens per session, growing if alwaysRead grows; contained by review discipline on the manifest (its integrity is already gated). A summarized-injection variant remains possible later, and the registry toggle can pause delivery instantly.

Coverage. Delivery exists for the Claude Code harness only; other harnesses stay manifest-based manual reading until their emitters land — the asymmetry is stated in the docs and the registry note.

Conditional reading stays residual. readWhenRelevant reading remains the agent's responsibility (full injection would more than double the constant cost; the list-only choice is deliberate).

Not Decided Here

  • SessionStart-equivalent emitters for other harnesses.
  • Criteria for switching to summarized injection.
  • Deterministic enforcement of readWhenRelevant.
