AI レビュー記録を advisory からハードゲートへ昇格する

この資料は、「実装 PR には AI レビュー記録を残す」という名目ルールを、記録の実在・指摘の明記・最終コミットとの一致を機械検証するハードゲートに変えることの承認を求めます。品質ゲート3部作（#79→#81→#80）の第1弾です。

承認のお願い（Requested Approval）

  1. 記録の実在を強制する。実装・統制ファイルを変更する PR は、PR 本文または PR コメントに「AI Review Record」（旧 Codex Review Record 見出しも受理）が無ければ CI が fail します。docs のみの PR は対象外。
  2. 「最終コミットのレビュー」を強制する。記録の Reviewed commit: は PR の【現在の】head コミットと一致しなければなりません。古いコミットの記録では fail — レビュー後に足したコードが未レビューのままマージされる穴を塞ぎます。あわせて明示的な Findings セクション（「指摘なし」も明記）を要求します。
  3. 統制コードを対象に含める。spec-before-implementation と異なり、ガードレールスクリプト・ワークフロー・agent policy も対象です — 統制コードこそ独立の目が必要だからです。
  4. CI 権限の最小追加。PR コメントを読むため、human-review-artifact ジョブに read 権限（pull-requests / issues）を追加します。書き込み権限は追加しません。

リスク（Risk）

記録の中身までは保証しない。このゲートが検証するのは構造（実在・Findings・コミット一致）であり、レビューの質そのものではありません。形だけの記録は書けます — それを塞ぐ独立性の強制は第2弾（#81）で行い、本ゲートはその土台です。

運用フローの変化。実装 PR は「push → 最終コミットを独立レビュー → 記録を本文に入れて PR 作成」の順になります。PR 作成後にコミットを足した場合は、再レビューして記録コメントを追加しないと CI が赤のままです（意図された摩擦です）。

タイミング。push 直後にコメントで記録を足す場合、CI のコメント取得と競走になりえます（数秒〜数分）。実運用では本文記載を推奨します。

決めないこと（Not Decided Here）

  • レビューの独立性（作成コンテキスト≠レビューコンテキスト）の強制 — 第2弾 #81。
  • 必読文書の決定的強制 — 第3弾 #80。
  • 特定のレビューツール（Codex／Claude／外部レビュアー）の選定。プロトコルはツール中立のまま。
