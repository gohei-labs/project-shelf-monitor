Review artifact required on every pull request

This review asks for approval to retire REV-01's conditional predicate and require a review artifact on every PR — because the predicate read text the gated agent writes, a failing gate was passed by rewording, with no false statement anywhere.

Requested Approval

  1. Make the artifact unconditional. The CI job invokes check-human-review-artifact.ps1 with its existing -RequireArtifact switch: every PR body must link an existing docs/{en,ja}/changelog/reviews/*.html artifact. This is the same graduation the AI Review Record made in change record 0075 (docs-only exemption retired), and follows the industry path the registry already cites: advisory or audit modes graduate to enforce.
  2. Record why in the rules. The registry's REV-01 entry, the review-artifacts spec, and the code-review standards now state the unconditional rule and preserve the incident: on PR #117 the wording-based predicate was silenced by editing the PR body — the requirement's trigger lived in agent-authored text.
  3. Accept the cost, scaled by depth. Every PR — including small ones — now needs an artifact. The spec's new rule: a small change earns a small artifact (a brief decision summary with the standard checked sections), never no artifact.

Risk

The cost is real and accepted by the owner: every PR needs an artifact, so friction rises on small changes (mitigated by depth scaling, not by exemptions — exemptions are where the rewording game restarts). The gate still verifies link and existence, not substance: a shallow artifact passes, and judging it remains the owner's job at merge time. This change removes REV-01's self-attested predicate; it does not claim other gates are clean — the same weakness class exists elsewhere and is listed below as follow-up.
