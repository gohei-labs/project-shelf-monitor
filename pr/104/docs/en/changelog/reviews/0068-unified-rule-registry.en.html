One rule registry, guardrail means enforced

This review asks for approval to unify the three rule inventories into monitor/registry.json and reserve the word "guardrail" for rules whose wired gate can block a change.

Requested Approval

  1. Single catalog: every rule is one entry in monitor/registry.json with an explicit domain (security / process-quality; the implicit "no domain = process" default is abolished and the registry gate enforces this). Precedent: NIST SP 800-53 Rev.5 merged separate inventories into one catalog, keeping distinctions as control families.
  2. Retire the LLM-GR-001..008 identifier scheme. Each item lives on as a registry entry (LLM-GR-003 joins as artifact-purpose-separation, its "Proposed" status expressed with the existing advisory + working-agreement vocabulary); a permanent mapping table in the rewritten registry doc keys old ids to registry ids. History is not rewritten.
  3. Vocabulary discipline: "guardrail" = a rule with a wired blocking gate (hard-gate / conditional-gate) — following AWS Well-Architected's layering (control = requirement, guardrail = its technical implementation) and informed by AWS Control Tower's documented rename of guardrails to controls "to align better with industry usage". Unenforced rules are working agreements; development.md is retitled Development Rules.

Risk

Taxonomy and documentation only — no gate behavior changes. The main risk is historical wording drift: old records keep LLM-GR ids and old titles; the permanent mapping table is the mitigation. The registry gate now fails any future entry lacking an explicit domain, preventing silent regression to the implicit default.
