プレビューコメントを確実に PR へ届ける

このレビューは Monitor Preview ワークフローにプレビューリンク投稿へ必要な pull-request の write 権限を与え、コメント失敗を警告として隠さずステップの失敗にすること の承認を求めます。

承認をお願いする事項

  1. Monitor Preview ワークフローのトークンを pull-requests: read から pull-requests: write に引き上げる。issues API 経由でプルリクエストにコメントするにはこの権限が必要で、issues: write だけでは足りない。これが最近の全 PR でプレビューリンクのコメントが欠けていた原因（403 が握りつぶされていた）。
  2. プレビューリンクのコメントをオーナー向けの制御手段として扱う：コメントの作成・更新に失敗した場合、ステップはプレビュー URL をログに出力したうえで fail する。これにより同じ退行が二度とサイレントに起こらない。

リスク

トークンが得る write 権限は本リポジトリのプルリクエストに限られ、実行はデフォルトブランチ由来の信頼された workflow_run コンテキストで行われる — PR 側で改変されたコードはこのトークンに触れられない（従来設計のまま）。失敗を隠さない方針により、将来権限が制限された場合はステップが明示的に壊れる。文書化された代替手段は MONITOR_PREVIEW_COMMENT_TOKEN シークレット。

ここでは決めないこと

  • MONITOR_PREVIEW_COMMENT_TOKEN シークレットを設定するかどうか。既定トークンで足りるようになる。
  • すでにオープン中の PR へのプレビューコメントの遡及投稿（PR #89 のリンクは本文へ手動で追記済み）。
  • プレビューが何をどこへデプロイするかの変更。
