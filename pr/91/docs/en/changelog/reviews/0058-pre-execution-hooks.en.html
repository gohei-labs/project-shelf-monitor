Move pre-execution-critical gates onto deterministic hooks (PreToolUse/Stop)

This review asks for approval to extend guards that previously fired only after the fact (check.ps1, CI) into deterministic hooks that fire before the agent acts.

Requested Approval

  1. Introduce the PreToolUse guard. File-tool writes are matched against the protected paths in agent-policy/policy.json and decided BEFORE execution. Command tools are checked against the destructive-command deny rules as a second deterministic layer under the permission boundary.
  2. Split protected paths into deny / ask. Issue #64 listed all four paths as deny. Instead, only unrecoverable targets (.git/, the generated .claude/settings.json and local grants) are deny; owner-review targets (monitor/registry.json, agent-policy/policy.json, .devcontainer/) are ask — a human approves at execution time. A blanket deny would stop the agent from ever registering a new guardrail, freezing the control system's own maintenance.
  3. Introduce the Stop gate. When the agent tries to end its turn, the full scripts/check.ps1 suite runs; while it fails the stop is blocked and the failing output is fed back. Infinite loops are prevented via stop_hook_active.
  4. Generate and gate the hook layer. Hook wiring is compiled from policy.json into .claude/settings.json; the registry gains agent-pre-execution-hooks (hard-gate). Disabled hook flags, missing scripts, or undeclared enforcement fail the extended existing gate.

Risk

Latency. PreToolUse spawns pwsh per tool call (~0.3-0.6 s); Stop runs the full check suite (tens of seconds) at each turn end. This is the cost of deterministic enforcement and is what Issue #64 explicitly ordered.

Over-blocking (false positives). Command matching is text-based, so a dangerous-looking string in a quoted literal right after a separator (e.g. inside a commit message) is occasionally denied. The error is on the safe side; the agent can rephrase and proceed. Quoted-context parsing is deferred to the sandbox work (#62).

Harness dependence. Hook wiring currently exists for Claude Code only; on other harnesses the post-hoc gates (CI) remain the only barrier until their emitters land. Note ask resolves to deny in non-interactive runs (fails safe).

Not Decided Here

  • Execution sandboxing, egress and credential-read controls (Issues #62, #63).
  • Hook/config emitters for other harnesses (Codex, Gemini, Cursor).
  • Parsing resolved commands (removing the limits of text matching).
  • Stop-hook speedups (e.g. skipping on a clean tree).
