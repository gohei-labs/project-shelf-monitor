AI review for governance data

This review asks for approval to make the AI-review-record gate treat governance data files as control state, closing the hole that let a registry-only or backlog-only PR merge without an independent AI review.

Requested Approval

  1. Adopt the principle. Governance data is control state, not documentation. Editing monitor/registry.json can disable a gate; project-components.json declares commands that CI executes; monitor/backlog.json records decisions. Changes to them get the same independent-AI-review requirement as implementation code.
  2. Adopt the mechanism. The three paths are added to check-ai-review-record.ps1's implementation/control pattern list. A PR touching any of them now needs a fresh AI Review Record (current head, differing author/reviewer contexts). Docs-only PRs stay exempt, unchanged.
  3. Accept the maintenance rule. The list stays hand-maintained: when a future governance data file is born, the review that creates it must extend this list in the same change.

Risk

Low. The gate only grows stricter; no existing requirement is relaxed. Exercised both ways before and after: a registry-only change previously classified as "no implementation/control files" (exit 0) and now demands a record (exit 1 without one); a docs-only change still passes. The residual risk is the hand-maintained list going stale when a new governance file appears — mitigated by the maintenance rule above.

Not Decided Here

  • Whether generated monitor HTML (monitor/*.html) should also require a record — it is derived output, kept in sync by freshness gates, so it stays exempt.
  • The backlog items BL-029..031 (preview publishing fixes) — separate work.
  • Automating the pattern list from the registry itself (a future refinement, not needed at three entries).
