Every rule states what it prevents

This review asks for approval to add a required "prevents" statement to all 38 rules and show it before the rule text on the monitor — so a card explains its purpose, not just its method.

Requested Approval

  1. Adopt the field. Every registry rule now carries a bilingual prevents: the concrete failure it exists to prevent, in plain language (registry schemaVersion 3 to 4). The gate (GOV-02) rejects a rule missing the field or either language, and the generator refuses to render it — a mechanism can never appear without its why.
  2. Adopt the presentation. The card list shows the prevents line under each title; the detail pane leads with a labeled "Prevents" block before the labeled rule text. Example (ENV-03, the card that prompted this): before — "declare a stack and check command before adding a component directory"; now the card first says "Stray code with no known way to test it: an app folder appearing because the agent guessed a stack from its name."
  3. Approve the 38 texts. The prevents statements for all 38 rules were written in this change (English and Japanese). They are editorial judgments distilled from each rule's note, change history, and gate behavior; any wording can be refined later without another schema change.
