Close the secret read-then-exfiltrate path

This review asks for approval to close the path where an agent reads existing credentials at run time and sends them out, from both the read side and the send side, at the harness.

Requested Approval

  1. Block the read side. Every credentialDenyRead path (~/.aws/credentials, ~/.ssh, etc.) compiles into Read-tool deny rules, and the PreToolUse guard denies any Bash/PowerShell command referencing those paths in any position (cat, grep, Windows path spellings included).
  2. Block the send side. New policy deny rules cover the external-send channels: gist sharing (gh gist directly and via the token wrapper) and request-body uploads (curl -d/--data*/-F/-T, wget --post-*/--body-*, including --flag=value spellings). Plain GET requests such as preview-link verification stay allowed.
  3. Block pushes to unknown remotes. The PreToolUse guard denies git push to any remote URL outside pushRemoteAllowedPrefixes (currently the gohei-labs org only). Named remotes (origin) stay allowed.
  4. Gate and surface it. Required deny rules gain gh-gist-share and curl-upload; an empty credentialDenyRead or pushRemoteAllowedPrefixes fails the gate. The registry gains credential-exfiltration-boundary (secrets category, hard-gate), documenting the threat the commit-time scan cannot see.

Risk

Over-blocking legitimate work. Request-body curl/wget is denied across the board, so a future legitimate API POST will also be blocked; the remedy is an explicit policy edit (itself behind the ask gate). Likewise the credential-path guard can deny a command that merely mentions such a path — an error on the safe side.

Residual channels. Exfiltration via allowed GET query strings, the WebFetch tool, or inside TLS payloads cannot be text-blocked. These are documented, not hidden, and belong to the OS-level egress work (#62).

Matching limits. Command matching is text-based and loses to obfuscation (variable expansion, base64). The final barrier is the sandbox (#62).

Not Decided Here

  • OS-level egress control and sandboxing (Issue #62 — the next PR).
  • Domain controls for WebFetch / WebSearch.
  • Analyzing obfuscated commands (inspecting resolved commands).
  • Controls on secret access via environment variables.
