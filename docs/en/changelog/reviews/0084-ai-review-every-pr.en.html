AI review on every pull request

This review asks for approval to require an AI Review Record on every pull request, retiring the docs-only exemption — the simple rule replaces the classified one.

Requested Approval

  1. Adopt the simple rule. Every PR — code, governance data, or documentation — must carry a fresh AI Review Record (current head, explicit findings, differing author/reviewer contexts). The record gate no longer decides "does this PR need review?"; it only verifies the record.
  2. Retire the docs-only exemption. DEC-01's rule text, the protocol document, and the gate all drop it. The path classification (including change 0074's governance-data list) is kept for reporting only.
  3. Accept the cost. Even a typo-fix PR pays one independent review pass. The owner chose this trade explicitly after two scope questions in a row proved the classified rule surprising in practice.

Risk

Low and strictly tightening — no requirement is relaxed. Operational note: the record must exist when CI evaluates the PR, so the working practice is to put it in the PR body at creation (the known post-push comment-timing failure). Exercised both ways: a docs-only change previously passed with "no record required" (exit 0) and now fails without a record (exit 1); implementation paths behave as before.

Not Decided Here

  • Whether trivial-PR reviews may use a lighter review depth — the record format is unchanged; depth stays a judgment call within the protocol.
  • The CI-timing improvement for records posted after push (parked; body-at-creation avoids it).
  • Adding further governance-data files to the reporting classification (0074's maintenance rule continues).
