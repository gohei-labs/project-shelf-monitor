Promote the AI review record from advisory to a hard gate

This review asks for approval to turn the honor-system rule "every implementation PR posts an AI review record" into a hard gate that verifies the record exists, states its findings, and matches the final commit. Part 1 of the quality-gate trilogy (#79 → #81 → #80).

Requested Approval

  1. Enforce record existence. A PR that changes implementation or control files fails CI unless the PR body or a PR comment contains an "AI Review Record" (the legacy Codex Review Record heading is also accepted). Docs-only PRs are exempt.
  2. Enforce final-commit review. The record's Reviewed commit: must match the PR's current head commit; a record for an older commit fails — closing the hole where code added after a review merges unreviewed. An explicit Findings section ("No findings" stated, not implied) is also required.
  3. Include control code in scope. Unlike spec-before-implementation, guardrail scripts, workflows, and the agent policy are NOT exempt — control code is exactly what needs independent eyes.
  4. Minimal CI permission addition. The human-review-artifact job gains read permissions (pull-requests / issues) to fetch PR comments. No write permissions are added.

Risk

The gate does not guarantee review substance. It verifies structure (existence, Findings, commit match), not review quality; a hollow record is still writable. Closing that requires the independence enforcement in part 2 (#81), for which this gate is the foundation.

Workflow change. Implementation PRs now go: push, independently review the final commit, open the PR with the record in the body. Adding commits after opening requires re-review plus a new record comment, or CI stays red (intended friction).

Timing. Posting the record as a comment right after a push can race CI's comment fetch by seconds to minutes; putting the record in the PR body is the recommended practice.

Not Decided Here

  • Enforcing review independence (authoring context != reviewing context) — part 2, #81.
  • Deterministic required-reading enforcement — part 3, #80.
  • Choice of review tool (Codex / Claude / external reviewers); the protocol stays tool-neutral.
