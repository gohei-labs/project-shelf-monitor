レジストリ scope フィールドの検証

このレビューは、レジストリ整合ゲートが、欠落・不正なルールの scope を拒否するようにする承認を求めるものです — domain や code と同様に scope を検証する、スキーマの堅牢化です。

Requested Approval

  1. scope を強制する。check-registry.ps1（GOV-02）は、各ルールが scope を宣言することを必須にし、generic / bilingual / product 以外の値を拒否します。既存の domain 検証と同じ形で、ローカルと CI で失敗させます。現行 37 ルールはすべて無改変で通過。
  2. stack は先送り。scope: stack は最初のスタック宣言まで意図的に拒否のまま。導入は先送りのスキーマ作業の一部で、この許可集合を意図的に拡張します — 値を早まって設定できないようにします。

Risk

低。チェッカーのみの変更 — レジストリのデータ・配線・モニター出力は一切触らず、37 ルールはすべて既に妥当な scope を持つ。唯一の留意点：scope: stack を導入する際は、ここの許可集合を同じ変更で拡張する必要がある。これは意図的で、新しい scope 値は静かに紛れ込むのではなくゲートの意識的な編集を強制すべき、という設計。

Not Decided Here

  • 妥当だが層が誤っている scope（#101 のような）を捕まえること：それは分類テスト／人によるレビューの判断のまま — enum チェックは正しい層を決められない。
  • scope: stack の導入と backend-checks / frontend-build の再スコープ（最初のスタック宣言時）。
  • マージゲート自体が強制されるか — Issue #102（プラン制限。別途のオーナー判断）。
  • GOV-02 のルール文を、検証するフィールドを列挙するよう拡張するか（現状はプロセス文が汎用のまま）。
