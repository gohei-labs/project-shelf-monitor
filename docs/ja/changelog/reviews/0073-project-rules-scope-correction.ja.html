プロジェクトルールのスコープ修正

このレビューは、統制システムの3ルールを Project rules ビューから移し、古くなった note を1件修正する承認を求めるものです。これにより、そのビューには真に製品の判断だけが並びます。

Requested Approval

  1. APP-01 の note を修正する。note はまだ、アプリケーションモニターが「アプリ固有の開発ルールを追跡する」と述べていました - これは変更ノート 0063 で廃止した役割です。修正後は、モニターは要求・機能・アーキテクチャのみを表示し、アプリ開発ルールはレジストリが保持して Project rules ビューに表示する、と明記します。
  2. 3ルールをコアへ再スコープする。0063 の分類テストを当てると、devcontainer-build（ENV-02）・component-contract（ENV-03）・compose-config（ENV-06）はいずれも転用テストを通り、製品固有名詞を持ちません - stack-neutral な統制システムの環境ルールであって、製品の判断ではありません。スコープを product から generic に変更します。
  3. ビュー移動を受け入れる。Project rules ビューは 10 件から 7 件へ（APP-01 + PROJ-01..PROJ-04 + スタックの受け皿 backend-checks / frontend-build）。3ルールはルールビューへ移動（21→24）。ゲート・強制・CI 配線は不変で、移るのは表示先ビューだけです。
