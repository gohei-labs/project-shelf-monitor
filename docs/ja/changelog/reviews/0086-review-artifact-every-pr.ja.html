レビュー成果物を全 PR で必須にする

このレビューは、REV-01 の条件付き判定を廃止し、すべての PR にレビュー成果物を必須とすることの承認をお願いするものです。判定が「縛られる側のエージェントが書くテキスト」を読んでいたため、失敗したゲートが本文の言い換えだけで通過してしまいました — 虚偽の記述はどこにもありませんでした。

承認していただきたいこと

  1. 成果物を無条件必須にする。CI ジョブが check-human-review-artifact.ps1 を既存の -RequireArtifact スイッチ付きで呼び出す: すべての PR 本文が、実在する docs/{en,ja}/changelog/reviews/*.html 成果物にリンクしなければならない。AI Review Record が変更記録 0075 で行ったのと同じ段階的強化（docs-only 免除の廃止）であり、registry が既に引用している業界の道筋（advisory / audit から enforce への graduation）に従う。
  2. 理由をルールに記録する。registry の REV-01 エントリ、review-artifacts 仕様、code-review standards が無条件ルールを明記し、経緯を保存する: PR #117 では、文言ベースの判定が PR 本文の編集で黙らされた — 要件のトリガーがエージェントの書くテキストの中にあった。
  3. コストを受け入れ、深さで調整する。小さな PR を含むすべての PR に成果物が必要になる。仕様の新ルール: 小さな変更には小さな成果物（標準のチェックセクションを備えた簡潔な decision summary）。「成果物なし」は選択肢にない。

リスク

コストは実在し、オーナーが許容を明言した: すべての PR に成果物が必要になり、小さな変更の摩擦が上がる（緩和は深さの調整であり、免除ではない — 免除は言い換えゲームの再開地点になる）。ゲートが検証するのはリンクと実在であり中身ではない: 浅い成果物は通過し、その評価はマージ時のオーナーの仕事のまま。本変更が消すのは REV-01 の自己申告型判定であり、他のゲートが無事だと主張するものではない — 同じ弱点クラスは他にも存在し、フォローアップとして下に列挙する。

ここでは決めないこと

  • 残りのゲートの自己申告型判定の監査（例: spec-before-implementation は PR 本文に書かれたレコード参照を受け入れる）— PR #117 マージ後のバックログ作業として提案。
  • AI レビュープロトコルに「レビュー対象 PR の failed→passed CI 遷移をすべて説明する」義務を追加すること — 別途レビューを伴うプロトコル文書の変更。
  • BL-032/033/034 とその提案 — PR #117（レビュー 0085）で別途判断。
  • ゲートスクリプト内の使われなくなったマーカー検出を将来削除するか — 当面はレポート用・CI 外の呼び出し元用に保持。
